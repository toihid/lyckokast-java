Die.java - Implementation

Purpose

Represents a single die with configurable number of sides

Key Methods

public class Die { private int value; private int sides; private Random random; // Roll the die public void roll() { value = random.nextInt(sides) + 1; } // Get current value public int getValue() { return value; } }

Design Decision

Uses Java's Random class for generating values between 1 and the number of sides. Validates minimum of 1 side in constructor.

Player.java - Implementation

Purpose

Manages player information and dice collection

public class Player { private String name; private int score; private ArrayList<Die> dice; // Roll all player's dice public void rollDice() { for (Die die : dice) { die.roll(); } } // Calculate total of all dice public int getDiceTotal() { int total = 0; for (Die die : dice) { total += die.getValue(); } return total; } }

Input Validation Strategy

The Challenge

Users can enter anything - letters, symbols, out-of-range numbers, or nothing at all!

private static int getValidInt( Scanner scanner, String message, int min, int max) { while (true) { System.out.print(message); String input = scanner.nextLine().trim(); try { int number = Integer.parseInt(input); if (number >= min && number <= max) { return number; } System.out.println("Enter a number between " + min + " and " + max); } catch (NumberFormatException e) { System.out.println("Please enter a whole number."); } } }

Challenges We Overcame

🔴 Challenge 1: Input Validation

Problem: Game crashed when users entered non-numeric values

Solution: Implemented try-catch blocks with NumberFormatException and created reusable validation methods

🔴 Challenge 2: Multiple Winners

Problem: Initially only considered single winner scenarios

Solution: Redesigned winner logic to find highest score first, then collect all players with that score

🔴 Challenge 3: Scanner Management

Problem: Scanner closing unexpectedly or no input available

Solution: Added hasNextLine() checks and proper exception handling

🔴 Challenge 4: Code Duplication

Problem: Similar validation logic needed in both game modes

Solution: Created reusable static methods for shared functionality
