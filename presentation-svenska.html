Die.java - Implementation

Syfte

Representerar en enskild tärning med konfigurerbart antal sidor

Viktiga metoder

public class Die { private int value; private int sides; private Random random; // Kasta tärningen public void roll() { value = random.nextInt(sides) + 1; } // Hämta aktuellt värde public int getValue() { return value; } }

Designbeslut

Använder Javas Random-klass för att generera värden mellan 1 och antal sidor. Validerar minimum 1 sida i konstruktorn.

Player.java - Implementation

Syfte

Hanterar spelarinformation och tärningssamling

public class Player { private String name; private int score; private ArrayList<Die> dice; // Kasta alla spelarens tärningar public void rollDice() { for (Die die : dice) { die.roll(); } } // Beräkna totalen av alla tärningar public int getDiceTotal() { int total = 0; for (Die die : dice) { total += die.getValue(); } return total; } }

Strategi för indatavalidering

Utmaningen

Användare kan mata in vad som helst - bokstäver, symboler, siffror utanför intervallet eller ingenting alls!

private static int getValidInt( Scanner scanner, String message, int min, int max) { while (true) { System.out.print(message); String input = scanner.nextLine().trim(); try { int number = Integer.parseInt(input); if (number >= min && number <= max) { return number; } System.out.println("Ange ett nummer mellan " + min + " och " + max); } catch (NumberFormatException e) { System.out.println("Vänligen ange ett heltal."); } } }

Utmaningar vi övervann

🔴 Utmaning 1: Indatavalidering

Problem: Spelet kraschade när användare angav icke-numeriska värden

Lösning: Implementerade try-catch-block med NumberFormatException och skapade återanvändbara valideringsmetoder

🔴 Utmaning 2: Flera vinnare

Problem: Tänkte initialt bara på en vinnare

Lösning: Omdesignade vinnarlogiken för att först hitta högsta poängen, sedan samla alla spelare med den poängen

🔴 Utmaning 3: Scanner-hantering

Problem: Scanner stängdes oväntat eller ingen indata fanns tillgänglig

Lösning: Lade till hasNextLine()-kontroller och korrekt undantagshantering

🔴 Utmaning 4: Kodduplicering

Problem: Liknande valideringslogik behövdes i båda spellägena

Lösning: Skapade återanvändbara statiska metoder för delad funktionalitet
